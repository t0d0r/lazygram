# 2026-10-31 - QR login, no environment variables

## Done

- `lazygram login` now links by QR code the way nchat does (gotd
  `QR().Auth`, update dispatcher for the login-token signal); two-step
  password asked once, hidden. Phone/code prompts removed.
- `internal/qrcode`: QR to terminal text, half-block rendering identical to
  nchat's (light modules as foreground, 4-module quiet zone), `-ascii` mode.
  Uses rsc.io/qr, already a gotd dependency.
- All `LAZYGRAM_*` environment variables removed. State directory from
  `-data` (default `~/.local/state/lazygram`); Telegram application
  registration asked once at login and stored in `telegram/app.json` (0600),
  or embedded at build time with ldflags (`make build TG_API_ID= TG_API_HASH=`).
- Subcommands: `lazygram` (telegram), `lazygram demo`, `lazygram login`.
  Without a linked account the default start exits 2 and prints how to link
  or run the demo. A session that is no longer authorized gives the same hint.
  Connect happens before the TUI starts, with a 45s limit.
- Telegram connector lists all dialogs (100 most recent) with generated
  aliases (username, else title slug, de-duplicated); per-chat selection via
  config removed. Sync is change-driven: one getDialogs per poll, history
  only for chats whose top message id moved; first-run backlog 50 per chat;
  FLOOD_WAIT up to 60s slept once and retried. Poll 10s for telegram.
- Makefile: `run` (telegram), `demo`, `login`, `smoke` (demo), all on `.state/`.

## Decisions

- nchat's API id/hash are not copied: nchat's SCOPE.md asks forks to get
  their own, and a shared registration gets throttled or banned. The
  one-time prompt plus optional build-time embed is the closest to nchat's
  "just run it" that stays honest.
- Dialogs with no top message are never fetched (saves a request per empty
  chat).
- Change-driven sync instead of polling every chat: 100 chats polled every
  10s would be flood-waited immediately.

## Open

- Never run against the real service; the operator must do the first login.
- Per-chat cursor is in memory: each start costs one history page per chat
  with messages.
- No reconnect; a dropped connection shows in the status line until restart.

## Addendum: registration from the environment

- `.envrc` added to `.gitignore` (it was untracked but not ignored).
- Resolution order at start: `app.json`, then `TG_API_ID`/`TG_API_HASH`
  (nchat's `TG_APIID`/`TG_APIHASH` accepted), then the build-time value.
  `lazygram login` stores what it took from the environment so later starts
  work without direnv. Half-set or invalid variables are reported by name.
- With direnv active, `make build` embeds the values through the existing
  `TG_API_ID ?=` Makefile variables as well.
