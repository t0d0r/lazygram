# 2026-11-02: autojoin

## Done

- At start a window opens for every chat with unread messages again,
  people, groups and channels. The start check ran only when no chat
  list was cached, so after the first run it never ran; it now runs once
  a session on the first chat list from the service.
- Windows restored from the last session take their chat's unread count
  from the service (except the window shown), as specs/ui.md already
  said ("unread comes from the service again").
- `/autojoin [on|off]`: on by default, kept in the state store under
  `autojoin`; off stops the windows opening at the next start. No
  argument shows the setting. It never opens or closes windows in the
  running session.
- The start notice names the windows with unread messages:
  `-!- 12 chats, 3 with unread messages: 2:#news (4), 3:@alice, ...`,
  cut after four as `+N more`; with autojoin off it says so and points
  at `/list`. The window list format is shared with the arrival status
  (`whereList`).

- Tab after a command completes its own first-argument words, whatever
  the spelling (`/autojoin on|off`, `/read-receipts on|off`, `/clip
  auto|osc52|tool|off`, `/win list` for `/j` and `/query` too), and chat
  names only where a chat fits: the first argument of `/win`, `/msg`,
  `/whois`, `/list`, the text of `/me` and `/edit`, and message text.
  Before, every command completed chat names, so `/autojoin @...` came
  up; the old spelling-keyed table also had a `/l` that is no command.

## Decisions

- The name is `/autojoin`, after IRC clients joining their channels on
  connect; `/join` stays an alias of `/win`.
- Opened windows fetch their messages when first shown, as before, so a
  start with many unread chats sends no burst of requests.
