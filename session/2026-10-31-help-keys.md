# 2026-10-31 help and keys split

Branch `feature/help-keys`, worktree of lazygram. Not committed.

## What was done

- `/help` (and `/?`, `/h`, F1) now prints the command reference only:
  the `Commands` block, one `/name` per line, ending with the line
  `Keyboard shortcuts: type /keys.` The `/help` entry reads "this command
  list (F1 too)" and a `/keys` entry follows it.
- New `/keys` (`/shortcuts`, `/bindings`) prints the key reference: the
  `Keys` block that used to follow the commands in the combined output,
  with its notes on themes, clickable text, mouse, windows and names.
  The F1 line there reads "the command list (/help); /keys prints this".
- Both print the same way: focus the server window (window 0) and queue
  plain lines through `slowPrint`, one line per tick, no stamp or marker.
  `/redraw` in window 0 still drops a queued print.
- Decision: the combined output had grown past one screen; the commands
  are what a new user needs first, so they stand alone and point at the
  keys. F1 keeps its spec meaning (command reference) so no key changed.
- `command.Names()` picks the new names up, so Tab completes `/keys`.
- `/help` spells out every short form the parser table accepts, as
  `also /x, /y` on the command's line or a continuation line (`/win is
  also /w, /window, /j, /join, /query` under the three `/win` usages,
  the same for `/open`). Every help line is at most 70 columns; the
  long `/send`, `/redraw`, `/edit`, `/mouse`, `/fx` and `/names` lines
  wrapped onto a continuation. Reason: the first split left aliases
  such as `/exit`, `/sync`, `/e` and `/rm` undocumented anywhere a user
  could see them.
- Drift guard, two layers: `TestHelpTextCoversEveryName` walks the
  parser table and requires `/name` in `HelpText` as a whole word (start
  of text or after a space; followed by space, comma, newline or the
  end, so `/win` does not satisfy `/w`), plus the 70-column cap, the
  closing `type /keys.` line and no `Ctrl-` text. In the TUI,
  `TestHelpPrintsSlowlyWithoutIndent` drains `/help`, splits the rendered
  lines on spaces and commas and requires each `command.Names()` entry
  as a whole field. Removing one alias line was checked to fail both.
- `specs/ui.md` Short forms paragraph now lists every alias.
