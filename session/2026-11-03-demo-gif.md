# 2026-11-03: README demo GIF

## Done

- docs/demo.gif (1180x660, about 34 s, 3.4 MB) replaces docs/screenshot.svg
  in the README; the SVG, an old capture without the start hints, is
  removed. The GIF shows, in order:
  - `lazygram login`: the QR login screen, then `linked; start lazygram to
    read your chats`;
  - `lazygram demo`: the server window (banner, the replayed demo feed,
    the start notices);
  - `/list`, Down, Down, Enter: @linus; a reply sent with Ctrl-X;
  - `/open`: the demo picture drawn in the window;
  - `/win @demobot`, `/press 1`: the bot's buttons and the answer;
  - `/win 0`, `/search demo`: the pager with the matches highlighted.

## How it was made

- vhs 0.12.1 (charmbracelet; needs ttyd and ffmpeg), Menlo 15, theme
  `nord`, 20 frames per second, a colourful window bar. The tape and its
  helper stayed in the session scratchpad, as the SVG tooling did before;
  rebuilding the GIF means writing them again from this description.
- The binary was built from master (`make build`, version
  v0.4.25-2-g2d1de74 in the banner) and ran with `-data` on a scratch
  directory, never the default state directory.
- The login screen is not a real login: no connection to Telegram is
  made. A small helper, built inside the module only to import
  `internal/qrcode`, prints the text `lazygram login` prints and a QR
  code of `tg://login?token=` with an invented token (the SHA-256 of a
  fixed phrase), which Telegram rejects. A live login token must never be
  recorded or published.
- The data directory was warmed in the hidden part of the tape (the demo
  started once and quit), so the chat list is cached: on a fresh
  directory the start notices often name the chats by id (todo).
