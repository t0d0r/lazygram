# 2026-11-03: vim mode

## Done

- `/vim on|off` (internal/tui/vim.go): an optional vim mode, off by
  default, kept in the state store under `vim` (absent or unreadable
  means off), a `vim` row in `/settings`, Tab completes `on`/`off`, a
  `/help` line, two `/keys` entries, a start hint. Every start and every
  `/vim on` begins in Insert with an empty kill buffer and no undo.
- The input: Insert is today's key map except Esc. Esc enters Normal,
  keeps the text, steps the cursor back one character and still arms Esc
  then a digit (so `0` right after Esc is window 0, else the line
  start). Normal never inserts a typed character: motions (`h l w b e 0
  ^ $ j k`), the ways into Insert (`i a I A o O`), edits (`x X D dd dw cw
  cc S C r`), a one-level undo `u`, `p`/`P` from lazygram's own kill
  buffer (memory only, never the clipboard), scrolling (Ctrl-E/Y/D/U/F/B,
  `gg`, `G`), `gt`/`gT`, and `:` `/` `?` to start a command or a search.
  Enter, Ctrl-X, Tab, the arrows, PgUp/PgDn, the other Ctrl keys, the
  mouse and a paste keep their meaning; sending keeps the mode. With
  "Enter sends" on, Ctrl-X's line break in Normal goes after the
  character under the cursor. Tab (with text) and Ctrl-W in Normal act
  as `a`, the key and Esc (`vimAppendKey`): they take the character
  under the cursor, then the cursor steps back, so `hi @ali`, Esc, Tab
  completes `@alice` and a second Tab lists as in Insert. `NORMAL` on
  the status line after the window tag.
- The lists (`/list`, `/win`, `/settings`) and the `/search` pager open
  in a Normal mode of their own: `j`/`k`, `h`/`l` (buttons, setting
  values, the search cursor), `gg`/`G`, Ctrl-D/Ctrl-U, Enter as before,
  `q` closes without arming a digit, Esc closes; `i`, `/` and `:` enter
  their Insert to narrow or type a command. A command line run from a
  list leaves the list it opens in Normal; the input keeps its own mode
  while a list is open. The rule reads `/ to narrow` in Normal.
- specs/ui.md (a Vim mode section with full key tables and Decision
  lines; Modes, commands table, Settings menu, Completion, Status line,
  Keys), specs/README.md, docs/usage.md (a Vim mode section).
- Tests in internal/tui/vim_test.go: the setting, every Normal key, the
  lists and the pager, and key-for-key comparisons of Insert with vim
  off and of the keys Normal leaves alone; the settings tests list nine
  rows. Each new test was checked against mutants of the code it
  guards; the one survivor cannot be observed (`/vim on` resets the
  state it changes).
- Built in a worktree by two implementing agents (the input, then the
  lists, the pager and the spec), reviewed for correctness, spec
  conformance and test strength, each finding verified by a second
  agent: 10 confirmed and fixed (Ctrl-X in Normal split the last
  character onto a new line and a double Ctrl-X then changed the draft;
  the `w`/`e` end-of-input rule and the kill buffer's lifetime in the
  spec; comments that named only the input; six test gaps), 1 refuted:
  Tab and Ctrl-W in Normal worked on the text before the character
  under the cursor, as the spec then said, so `hi @ali`, Esc, Tab gave
  `hi @alice i`. That behaviour was changed afterwards (above), the
  spec with it. The change had its own review in two lenses with each
  finding verified: 2 confirmed and fixed (test gaps: a second Tab that
  lists, an empty line inside the input), 4 refuted (no undo for these
  keys and Ctrl-W crossing a line break are older and shared with other
  keys, now open below; grapheme clusters were already right, and are
  now pinned by a test).

## Decisions

- Off by default, so nothing changes for anyone who does not ask; with
  vim off every key does what it did before.
- Starts in Insert: a chat client is mostly typing.
- Esc then a digit keeps switching windows, so the Alt-less habit
  survives.
- Normal never types: a stray key cannot type or send anything. Enter
  and Ctrl-X do the same in both modes, so sending never depends on the
  mode.
- vi's details where the request left them open: the cursor sits on a
  character, `^`/`I` skip leading blanks, `cw` keeps the blank after the
  word, a second `u` undoes the undo. `dd`, `cc` and `S` clear the whole
  input (one message), not one line. No counts, registers or multi-level
  undo.
- Lists open in Normal, since in a list one mostly moves; `:` starts a
  command in a list as in a window.
- Tab and Ctrl-W in Normal take the character under the cursor, as
  Ctrl-X's line break does: on the text before it they left that
  character behind, so the same keys did one thing before Esc and
  another after it.

## Open

- In Normal the keys that keep their meaning (Tab, Ctrl-W, Ctrl-K,
  Backspace, Delete, a paste) keep no undo snapshot: `u` skips them and
  can take back the change before them too (todo).
- Ctrl-W breaks words only at spaces, so in a multi-line input it
  deletes across a line break, in every mode; vi stops at the line
  start (todo).
- Not tried on a real terminal with a live account; the demo was run in
  a pseudo-terminal.
