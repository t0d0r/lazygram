# 2026-11-02: fuzz targets and the bugs they found

## Done

- Go fuzz targets (`func Fuzz...`, seeds run with `go test`):
  - internal/domain: FuzzMentionsIn (an independent reading of the
    mention rule in both directions: every name returned is a mention,
    every inserted mention is returned), FuzzTranslit, FuzzMatcher,
    FuzzPrefixMatch, FuzzResolveMember, FuzzResolveChat, FuzzMembers,
    FuzzWithParticipants, FuzzIsImageName.
  - internal/command: FuzzParse. internal/update: version parsing,
    FuzzVerify (the digest must sit on the line of the file's own
    name), FuzzExtractBinary. internal/config: FuzzParseApp,
    FuzzAppFromEnv, FuzzLoadApp (errors never print the values).
  - internal/tui: FuzzSanitize, FuzzSanitizeName, FuzzWrapText (no
    line wider than the window, no grapheme cluster split),
    FuzzURLsOf (link extent per specs/ui.md, saved failures under
    `testdata/fuzz/FuzzURLsOf`), FuzzHighlight.
- `make fuzz` runs every target for `FUZZTIME` (default 10s) and stops
  when a package's tests do not build.
- Bugs found and fixed, each with a seed or test that fails on the old
  code:
  - An `@name` inside a `www.` link that follows a no-break space (or
    another multi-byte space) was counted as a mention, so a link from
    a web page made up a member.
  - A word of emoji with a variation selector (a red heart) was cut at
    twice the room, so a message line overflowed the window; grapheme
    clusters (ZWJ families, flags) are no longer cut apart.
  - Links ran on over Unicode spaces (a French no-break space before
    `!`), so Tab after `/open` offered links `/open` refused.
  - `https://!` became a clickable link; a scheme with nothing after it
    is no link now.
  - A balanced closing bracket was cut off a link (`Go_(game)`), so a
    click opened something else than a double click copied; a backtick
    now ends a link as it ends a word.
  - Search highlighting sliced the original text with the offsets of
    its lower-cased copy, wrong for letters whose lower case has another
    byte length (U+0130, U+212A); spans are computed rune by rune.
  - The application hash accepted invalid UTF-8, which app.json then
    stored altered; and a hand-edited app.json made LoadApp print the
    api_id in its error, against specs/security.md.
  - Self-update extracted at most 64 MiB of the binary without an error
    when the entry was larger, which would have installed a cut binary;
    a larger entry is now an error (header size and actual bytes).
- specs/ui.md: the mention rule (Latin run, 4 to 32, link test ignoring
  case) and the link extent stated outright; specs/release.md: the cap
  on the extracted binary; specs/security.md: the fuzz targets.
- Each group was written by one agent and checked by a second one that
  re-ran the targets and tried the regression tests against the old
  code; the confirmed problems (one-way properties, a check that could
  not fail, the junk-link and bracket fixes) were fixed and reviewed
  again.
