# 2026-11-03: /win last and the double Tab

## Done

- The last focused window (internal/tui/lastwin.go): the window current
  before the current one, Alt-Tab style, tracked by the window itself,
  so `/move` and closing other windows keep it; closing it leaves none.
  Every focus change sets it (through `focus`, the body of `switchTo`),
  except the first Tab of a double Tab. Session only.
- `/win last` (also `/w last`, `/j last`) switches to it and, repeated,
  toggles; with none it is the error `no last window`. `last` joins
  `list` as a fixed word of `/win` that Tab completes (so `/win l` is now
  ambiguous); a chat named last is `/win @last`.
- Double Tab on an empty prompt: the first Tab switches to the next
  window at once, as before; a second Tab within 400 ms (`tabGap`,
  exactly 400 ms included) with no key or focus change between goes to
  the window that was the last one before the first Tab, so another
  double Tab goes back. With no last window the second Tab is a plain
  Tab; a third fast Tab is a first Tab again; Shift-Tab is unchanged.
- A window an empty-prompt Tab showed and that is left within 400 ms is
  left as it was: its unread count comes back (less any message deleted
  meanwhile) and no read receipt is sent for it. A receipt for a window
  focused by such a Tab is therefore sent only once it has stayed current
  for 400 ms (`Model.after`, injectable for tests); every other focus
  path sends it at once as before.
- With vim mode (merged from master): Tab on an empty prompt is the same
  in Normal and Insert, double Tab included; `gt` / `gT` switch as
  Ctrl-N / Ctrl-P do, never part of a double Tab, their receipt sent at
  once (specs/ui.md, Vim mode; TestWinLastDoubleTabInVimNormal).
- specs/ui.md (Windows, the `/win last` row, Completion, Read receipts,
  Keys, start hints), docs/usage.md, `/help`, `/keys`, a start hint.
- Tests in internal/tui/lastwin_test.go (every focus path, timing edges,
  what breaks a double Tab, the restored counts, held and dropped
  receipts on the real timer wiring); two older tests adjusted (Tabs
  slower than 400 ms to walk windows; `/win li` and `/win la`
  completions). Each new assertion was checked against a mutant.
- Built in a worktree by one implementing agent, reviewed for
  correctness, spec conformance and test strength, each finding
  verified by a second agent: 9 confirmed and fixed (a window passed
  through with no last window lost its unread count and never sent its
  receipt; a held receipt was dropped when the user came back within
  400 ms; a nil timer would have crashed outside the tests; four test
  gaps), 3 refuted.

## Decisions

- The first Tab acts at once, so a single Tab stays immediate, as
  single clicks do.
- A read receipt tells the other side a message was read; a window
  flashed for a fraction of a second was not read, so its receipt waits
  400 ms and its unread count comes back.
- Fast Tabs no longer walk two windows: walking needs a pause over
  400 ms, or Ctrl-N / Ctrl-P.
