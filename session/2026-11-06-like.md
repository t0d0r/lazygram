# 2026-11-06: /like sends a reaction

## Done

- `/like [name]` sets the account's reaction on one message of the
  current chat window (internal/tui/like.go):
  - Names, matched without regard to case; `/like` alone is `like`:
    `like` (+1, thumbs up U+1F44D), `dislike` (-1, U+1F44E), `love`
    (heart, U+2764 without U+FE0F), `fire` (U+1F525), `laugh` (U+1F601),
    `sad` (U+1F622), `party` (tada, U+1F389), `clap` (U+1F44F), `thanks`
    (pray, U+1F64F), `ok` (U+1F44C), `think` (U+1F914), `eyes`
    (U+1F440). Each is in Telegram's standard reaction set as the Bot
    API's ReactionTypeEmoji lists it. Go source writes them as escapes.
  - Target: the newest message lazygram holds of the window's chat that
    someone other than the account sent and that has an id
    (`domain.LastFromOthers`). Own lines after it are skipped; never more
    than one message.
  - Checks, in order, each sending nothing: another name, an emoji or
    more than one word, in any window: `/like takes like, dislike, love,
    fire, laugh, sad, party, clap, thanks, ok, think or eyes`; window 0:
    `the server window has no chat; /win to a chat first`; a provider
    without `provider.Reactor`: `reactions cannot be sent with
    <provider>`; no target: `no message from someone else in <chat> to
    react to`.
  - Then `reacting E to ada "first words"...`, the request in the
    background (30 s), `reacted E to ada "first words"`; the reactions
    the answer carries are applied like a poll's (`applyChange`); a
    failure is `reaction failed: <why>` in red and in window 0. Nothing
    is focused or read.
- `provider.Reactor` (optional): `React(ctx, chatID, msgID, emoji)
  ([]domain.Change, error)`.
- Telegram: messages.sendReaction with the dialog's peer, the numeric id
  and one reactionEmoji, big and add_to_recent unset; FLOOD_WAIT retried
  once like every call; any updateMessageReactions in the answer
  returned as Reacted changes; documented refusals in words with the
  code (REACTION_INVALID, REACTIONS_TOO_MANY, PREMIUM_ACCOUNT_REQUIRED,
  CHAT_WRITE_FORBIDDEN / USER_BANNED_IN_CHANNEL /
  ANONYMOUS_REACTIONS_DISABLED / CHANNEL_PRIVATE, MESSAGE_ID_INVALID /
  MSG_ID_INVALID); MESSAGE_NOT_MODIFIED is done; others pass on as
  `telegram: reaction: ...`. Inert without a client.
- Demo: `React` in memory; the account's earlier reaction on the line
  is replaced (the paid star kept), later polls agree.
- `/help` entry and the Reactions note, Tab completes the twelve names
  (not the aliases), a start hint, `/like` in the window 0 refusal list.
- specs/ui.md (Reactions, Sending a reaction, with Decisions; commands
  table; short forms; Completion; hint lists), specs/providers.md
  (Reactor; Telegram sending; demo), docs/usage.md, todo/todo.md.

## Decisions

- One message by a rule visible on screen, the newest from someone
  else: a reaction is public and lazygram cannot take it back yet.
- A fixed vocabulary of ASCII names, each an emoji the API documentation
  lists, instead of any emoji: Tab-completable, typo-proof.
- Form before state in the checks, as `/close-others`.
- One spelling, `/like`; `/react` stays unknown.
- No removal (`/like off`): the documentation read (core.telegram.org
  api/reactions, the method's schema) does not say that an empty or
  absent list removes a reaction. Not guessed; todo.
- Nothing relies on the sendReaction answer carrying the reactions (not
  documented); without them the next poll of the messages on screen
  shows the change.

## Security note

A reaction is visible to the chat, so `/like` acts on exactly one
message, chosen by a rule shown in the status before the request, and
only on an explicit command. Names are a fixed ASCII list; no typed text
reaches the service. Tests and checks used fakes and the offline demo;
nothing was sent to a real account.
